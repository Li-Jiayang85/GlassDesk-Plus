# GlassDesk Plus 1.4.9

修三个窗口相关的老问题：Dock 在普通窗口前消失、最大化/全屏时压在窗口上、透明度滑杆没反应。

## 1. 最大化或全屏时 Dock 不再压在窗口上

**原因**：让位判定只看「真全屏」——前台窗口是否覆盖**整块显示器**。而最大化窗口覆盖的是**工作区**
（显示器减去任务栏），按整屏判定永远不算全屏，置顶的 Dock 就一直压在最大化窗口上面。

**处理**：

- 新增 `FullscreenDetector.ForegroundCovers(区域)`，把「覆盖工作区」也算进让位条件
- Dock 的让位判定改为：真全屏 **或** 覆盖工作区（最大化）→ 收起
- 还原窗口后延迟 700ms 二次确认再恢复，避免菜单/UAC 让 Dock 闪一下

**实测**（最大化浏览器窗口）：

```
最大化前        可见=True
最大化后 1.5s   100000000000000   ← 100ms 内收起，之后一直隐藏
还原后 2.0s     00000001111111111111 ← 约 800ms 后恢复
```

## 2. 打开普通窗口时 Dock 不再消失

**原因**：让位完全依赖 `FullscreenWatcher` 的 `onFullscreenChanged` 回调，而它**只在全屏判定翻转时**
才回调。窗口创建/切换过程中的瞬时状态可能触发一次误判，判定本身却没翻转，于是收起后没有对应
的恢复回调，Dock 就停在隐藏状态。

**处理**：改用看门狗的 `onStateInvalidated`（每个前台/位置事件都会通知），统一在 UI 线程用同一个
判定重新计算，收起与恢复走同一条口径，不会再出现「收起了却等不到恢复」。

**实测**：普通窗口前台、启动台打开、设置窗口打开，Dock 均保持可见。

## 3. 透明度滑杆现在整段有效

**原因**：玻璃染色量 `BodyTintScale` 对启动台是 `min(1, 2 × (1 - c))`，`c ≤ 0.5` 时恒为 1——
滑杆左半段完全焊死；对 Dock 更是**恒等于 1**，只有很淡的背景染色会变。所以拖滑杆几乎没反应。

**处理**：改成线性 `1 - c`，0 = 不透明、1 = 完全透明，整段行程都有反馈。

**实测**（Dock 区域平均亮度）：

```
透明度 0.0 -> 71.84
透明度 0.3 -> 73.75
透明度 0.6 -> 75.07
透明度 1.0 -> 77.58     ← 单调、可分辨
```

```

```

## 升级说明

覆盖安装即可。透明度数值含义与之前一致（0 不透明、1 透明），因为映射变线性，
同样的数值看起来会比以前更透一些，可在设置 → 外观里按喜好回调。
