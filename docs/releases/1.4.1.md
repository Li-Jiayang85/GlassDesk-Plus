# GlassDesk Plus 1.4.1

本版修复一个**必现的应用内更新缺陷**，并包含 1.4.0 的两项新功能（启动台批量删除、自定义托盘图标）。

## 修复：「更新失败：安装包信息无效」

**症状**：点「检查更新」能发现新版本，但一确认就变成

> 更新失败：安装包信息无效。

**原因**：更新通道里**两处对安装包文件名的认定不一致**：

| 位置 | 要求的资产名 |
|------|-------------|
| `UpdateClient.ParseRelease`（发现新版本） | `GlassDesk-**Plus**-<版本>-win-x64-Setup.exe` |
| `UpdateClient.ValidateInstaller`（下载/安装前校验） | `GlassDesk-<版本>-win-x64-Setup.exe`（**漏了 Plus**） |

于是它先按带 Plus 的名字认下安装包，紧接着又用不带 Plus 的规则把自己拒掉。
`ValidateInstaller` 在下载前与安装前各调用一次，所以两段都会栽在这里。

**修复**：`ValidateInstaller` 改用与 `ParseRelease` 相同的资产名，并补了单元测试
（`tests/GlassDesk.AppServices.Tests/UpdateClientTests.cs`）把两处钉在一起，
任何一边改名而另一边没跟上都会立刻失败。

**验证**：用产品自身的 `UpdateClient` 打真实 GitHub 走完整条链路——

```
已装 1.0.4 / 1.0.5 / 1.3.1 / 1.3.6 → 均发现 1.4.x
已装 1.4.1                        → 已是最新，不报错
真实下载 1.4.1 安装包             → 51.4MB 下载完成，sha256 与 release 摘要一致
```

## 新增功能（1.4.0 起）

## 启动台批量删除

- 在启动台任意图标上右键，菜单底部新增「多选…」：进入多选并自动勾选当前图标。
- **只看勾选角标判断选中**：多选时每张磁贴右上角出现勾选角标，左键单击即勾选/取消，可连续点选；勾上的就是会被删掉的。没有复选框，也没有底部工具条。
- **多选时「添加」旁边多出「取消选择」与「删除」**：顶部一行顺序为 `搜索框 | 取消选择 | 添加 | 删除`，「添加」始终在；删除按钮显示当前数量（如「删除 3 项」），未勾选任何图标时停用。删除用红色胶囊与其余按钮区分。（DockPanel 右靠按声明顺序从左往右排，所以 XAML 里必须先声明「取消选择」再声明「添加」。）
- 键盘：`Esc` 退出多选。**`Del` 键不再触发删除**——删除只由顶部按钮发起，避免误触。
- 选中项可跨页累计，删除时一并处理。
- 删除语义与原有单个「删除」完全一致：**只把图标移出启动台布局，不删除源文件、快捷方式或应用库记录**，随时可以重新添加。因此不做二次确认，仅提示「已从启动台移除 N 个图标」。
- 多选期间图标拖拽（长按拾取）自动禁用，避免「点选」被当成「拖拽」；退出多选即恢复。
- 多选时搜索框保持可用；但**已处于搜索状态时不能进入多选**（与原有整理限制一致），分组面板内同样不进入多选。

## 托盘图标自定义

- 设置 → **托盘图标** 新增独立小节。
- 「在通知区域显示 GlassDesk 图标」开关：关闭后立即从通知区域摘下图标，不留死图标；重新打开即恢复。
- 「托盘图标」下拉框可在**已有的自定义图标**之间切换——即此前在启动台给某个应用换过的那几张图（数据目录 `icons/custom-*`），并带实时预览；选择「内置图标」回到品牌标识。
- 复用应用库的自定义图标生命周期：不必单独复制文件，备份会连带这些图标一起保存；所选文件缺失时自动回退到内置标识，不会留下空白托盘位置。
- 非正方形图片按比例缩放后居中，不拉伸变形。

## 其它修复

- 图标拖拽放下后，松手时落在该磁贴上的合成点击不再被当成「打开这个应用」——此前走 OLE 放下返回启动台那条路绕过了原有的点击抑制标志。

## 已知问题：旧版本点「检查更新」报「此版本没有唯一的 Windows x64 安装包」

**症状**：1.0.4 及更早的安装版点「检查更新」，提示

> 无法检查更新，请确认网络连接后重试。
> 此版本没有唯一的 Windows x64 安装包。

**原因**：安装目录里残留了一个**上游产品带来的** `update-source.json`：

```
%LOCALAPPDATA%\Programs\GlassDesk\update-source.json
  → { "releasesApi": "https://api.github.com/repos/everlosttime/glassdesk-updates/releases/latest" }
```

代码的规则是「该文件存在则优先于内置默认源」，于是更新检查被导到上游作者的仓库。那里最新的
release 是 `v1.3.6`，资产名是 `GlassDesk-1.3.6-win-x64-Setup.exe`；而本分支只认
`GlassDesk-Plus-<版本>-win-x64-Setup.exe`，找不到就抛这句。**与本仓库的发布无关**，
本仓库的 release 是正常且可被识别的。

**修复**：删掉那个文件即可，程序会自动回落到代码内置的默认源（本仓库）。

```powershell
Remove-Item "$env:LOCALAPPDATA\Programs\GlassDesk\update-source.json" -Force
```

> 不要去上游仓库 `everlosttime/glassdesk-updates` 发 release——那是别人的仓库，
> 我们没有写权限，也不该往里发。`build/release.ps1` 的 `-ReleaseRepository` 参数
> 也不要指向它。

新的安装包不再包含该文件，所以全新安装与本次升级后的安装都不会再出现这个问题。

## 为什么从 1.0.5 跳到 1.4.0

本分支此前的版本号是 1.0.x，但**所有渠道上已有更高的版本号**：

| 来源 | 最高版本号 |
|------|-----------|
| 上游更新仓库（`everlosttime/glassdesk-updates`） | 1.3.6 |
| 本仓库历史标签 | v1.31（旧命名，实际低于 1.3.6） |
| 本仓库本次发布 | v1.0.5 |

`UpdateClient.ParseRelease` 的判定是纯数字比较（`version <= installed` 即视为没有新版），
所以版本号若停在 1.0.x：

- 1.0.4 用户能看到更新
- **1.3.6 老用户看不到**（1.0.x < 1.3.6）

发 1.4.0 后，任何已安装版本（1.0.4、1.3.6、1.31 等）点「检查更新」都会得到新版本提示。

## 发布清单（本次）

打包命令与资产命名是对更新客户端的硬约定，发布时不要改名：

```
资产：GlassDesk-Plus-1.4.1-win-x64-Setup.exe
标签：v1.4.1        标题：GlassDesk Plus 1.4.1
```

`UpdateClient.ParseRelease` 按名字精确匹配安装包，并要求该资产带上
`digest`（GitHub 自动生成 sha256）；名字不符会直接报「此版本没有唯一的 Windows x64 安装包」。
打包统一走 `build/package.ps1`，它已按此命名并会校验暂存目录。

发布前跑一次更新通道与托盘验收：

```powershell
# 离线 20 项：发布解析、命名一致、版本比较、draft/prerelease、缺摘要、更新源形状，
#            批量删除核心，托盘设置/图标渲染/缺失回退/显示移除往返
dotnet run --project tests/GlassDesk.UpdateAcceptance -c Release

# 含在线 27 项：真实发现新版本 + 下载安装包 + 核对 sha256
dotnet run --project tests/GlassDesk.UpdateAcceptance -c Release -- --online
```

它存在的理由正是本次这个缺陷：当时的验收只覆盖到「发现新版本」，而坏的是
「下载前校验」，所以漏了过去。现在 `U-01`/`U-03` 把 `ParseRelease` 与
`EnsureUsable` 的命名约定钉在一起，离线就能发现这类不一致。

托盘那几项里，`U-35` 只断言「显示/移除往返不抛错且状态干净」；**shell 是否真的接受图标**
（`TrayIcon.Show` 的返回值）作为诊断输出，因为在受限/自动化会话里 shell 会直接拒绝添加，
而同样的代码在正常桌面会话下是成功的——产品自己的 Dock 进程就一直在显示托盘图标。
把它算作失败只会制造假警报。
